Chapter 1 · Day 1 Creating the Project & Initializing Git

You open your terminal to start a brand new project. You create a folder my-app and run git init. Git creates a hidden .git directory inside your folder. This hidden folder is Git's brain — it stores every snapshot, commit pointer, and branch configuration locally on your computer.

# Create project folder and step inside mkdir my-app && cd my-app # Initialize Git repository git init
Git Cat Tip 🐱

Running git init turns a plain directory into a Git repository. Everything remains 100% local on your hard drive!

📦
Chapter 2 · Staging Creating Files & The 3-State Staging Pipeline

You write code in README.md and notes.md. When you type git status, Git highlights these files in red as UNTRACKED. To include them in your next snapshot, you run git add . to stage them into the Index. Finally, you run git commit -m "Initial commit" to permanently freeze your first snapshot in history!

# Check working tree status git status # Stage all modified and untracked files git add . # Freeze staged changes as a permanent snapshot commit git commit -m "Initial project structure"
Staging Pipeline ⚡

Working Directory ➔ git add ➔ Staging Area (Index) ➔ git commit ➔ Repository Graph.

🔀
Chapter 3 · Branching Feature Isolation with Lightweight Branches

You need to build a new login feature. Instead of risking breaking your stable main branch, you run git checkout -b feature-login. In Git, a branch is not a full directory copy — it is simply a 40-character pointer pointing to your current commit! You make changes, test freely, and commit safely without affecting main.

# Create new branch and switch HEAD pointer to it git checkout -b feature-login # Commit changes isolated on the branch git commit -m "Build user login form"
HEAD Pointer 📍

HEAD points to the branch you are currently standing on. Switching branches moves HEAD and updates your working disk files instantly.

🌐
Chapter 4 · Collaboration Multi-Developer Sync & GitHub Remotes

Your project goes open-source on GitHub! You publish your feature branch using git push -u origin feature-login and open a Pull Request. Meanwhile, another developer merges code into the canonical upstream/main repo. To update your local machine safely, you run git fetch upstream and git merge --ff-only upstream/main.

# Push branch to your GitHub fork git push -u origin feature-login # Fetch latest commits from upstream maintainer git fetch upstream # Safely fast-forward local main git merge --ff-only upstream/main
3-Copy Model 🏛️

Upstream (maintainer) ➔ git fetch ➔ Local (your laptop) ➔ git push ➔ Origin (your GitHub fork).

💥
Chapter 5 · Conflicts Facing & Resolving Merge Conflicts

A teammate edited the exact same line in config.json that you modified on your branch. When you attempt git merge feature-login, Git stops and warns: Merge conflict in config.json. Git places conflict markers in your file: <<<<<<< HEAD, =======, >>>>>>>. You open the file, delete the conflict markers, keep the combined correct code, stage with git add config.json, and run git commit to seal the 2-parent merge!

# Attempt merge — conflict occurs git merge feature-login # Open file, remove <<<<<<< markers, stage resolved file git add config.json # Complete merge commit git commit
No Need to Panic! 🛠️

Merge conflicts are simply Git asking a human to decide between two conflicting edits. If you ever feel lost, run git merge --abort to reset!

🛠️
Chapter 6 · Rescue Stashing, Rebasing & Reflog Rescues

When an urgent bug report arrives while your working tree has uncommitted edits, you run git stash to temporarily shelve your changes, fix the bug, and run git stash pop to restore your work. Later, if you accidentally run git reset --hard and a commit disappears from git log, you run git reflog to find its SHA, and run git checkout -b rescue <sha> to bring your lost commit back to life!

# Temporarily shelf uncommitted work git stash && git stash pop # View HEAD movement log to locate "lost" commit SHA git reflog # Rescue lost commit by pointing a new branch at its SHA git checkout -b rescue a1b2c3d
Git Ninja Master 👑

Congratulations! You now understand that Git is an immutable directed graph where nothing is lost and every state is recoverable!
