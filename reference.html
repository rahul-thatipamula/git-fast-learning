Command Category Safety Level Description & Usage Action
git init Basics Safe Initializes a new Git repository in the current directory. Creates the hidden .git folder to track snapshots.
git status Basics Safe Shows current branch, untracked files (??), modified files (M), and staged changes (A). Run whenever unsure what to do.
git status -s Basics Safe Prints a compact short status: ?? untracked, M modified unstaged, M staged. Ideal for quick terminal checks.
git add <file> Basics Safe Stages modified or untracked changes for the next commit. Use git add . or git add -A to stage everything in directory.
git commit -m "msg" Basics Safe Creates a permanent snapshot (commit) of staged files with an explanatory message. Adds a new point in history.
git commit -am "msg" Basics Safe Automatically stages all modified tracked files and commits them in one step. (Does not stage new untracked files).
git log --oneline --graph Basics Safe Prints commit history as a visual ASCII graph. Add --all to inspect all local and remote branches simultaneously.
git show <sha> Basics Safe Shows detailed commit information including author, date, message, and line-by-line diff changes introduced by that commit.
git diff / diff --staged Basics Safe git diff compares working tree against staging area. git diff --staged compares staged changes against last commit snapshot.
git restore <file> Basics Destructive Discards uncommitted local edits in working directory. Use git restore --staged <file> to unstage without losing edits.
git branch [-a|-m|-d|-D] Branching Safe git branch lists local branches. -a lists all local/remote branches. -m <new> renames branch. -d deletes merged branch; -D force deletes.
git checkout -b <name> Branching Safe Creates a new branch and switches HEAD pointer to it in one step. Equivalent to git switch -c <name>.
git switch <branch> Branching Safe Modern dedicated syntax to switch between existing branches. Leaves uncommitted edits intact if no path conflicts exist.
git merge <branch> Branching Adds History Merges target branch into current branch. Fast-forwards if possible, or creates a 2-parent merge commit. Use --no-ff to force merge commit.
git merge --ff-only <ref> Branching Safe Merges only if update can be fast-forwarded without creating a merge commit. Safest method for syncing local main with upstream.
git clone <url> GitHub Safe Downloads a complete copy of a remote GitHub repository to your local machine and configures origin tracking automatically.
git remote -v / add GitHub Safe Lists all configured remote repository URLs (fetch & push). Use git remote add upstream <url> to link original repo.
git fetch <remote> GitHub Safe Downloads commits and refs from remote repository without modifying working directory or local branches. Completely safe to run anytime.
git pull [--rebase] GitHub Adds History Fetches changes from remote branch and immediately merges (or replays with --rebase) into your current local branch.
git push -u origin <branch> GitHub Safe Uploads local commits to specified remote branch. -u sets upstream tracking. Use git push origin --delete <branch> to delete remote branch.
gh issue list / comment GitHub Safe GitHub CLI commands. gh issue list shows open issues; gh issue comment <id> --body "..." posts a comment to claim work.
gh pr create GitHub Safe Opens a Pull Request on GitHub asking maintainers to pull your pushed feature branch into their main branch.
git stash [pop|list|apply] Advanced Safe git stash temporarily shelves uncommitted changes. stash list views shelf, stash pop restores latest, stash apply restores without removing.
git rebase [-i] <branch> Advanced Rewrites History Replays your branch commits on top of another branch for a linear history. -i enables interactive squashing, editing, and reordering.
git push --force-with-lease Advanced Rewrites History Safely force-pushes rebased or amended branches. Fails if someone else pushed new commits to the remote branch in the meantime.
git commit --amend Advanced Rewrites History Replaces the most recent commit with a new commit containing currently staged changes and/or a updated commit message.
git reset [--hard|--soft] Advanced Destructive Moves HEAD pointer back. --soft keeps changes staged. --hard resets working directory and index (recoverable via reflog).
git reflog Advanced Safe Records every position of HEAD over time. Use this to find SHAs of "lost" or reset commits and recover them with git checkout -b rescue <sha>.
git cherry-pick <sha> Advanced Adds History Applies the exact changes introduced by a specific commit onto your current branch as a new commit.
git revert <sha> Advanced Adds History Creates a brand new commit that reverses all changes of a previous commit. Completely safe for public or shared branches.
git clean -fd Advanced Destructive Removes untracked files (-f) and directories (-d) from your working directory. Run git clean -n first to preview!
touch <file> Shell Safe Creates a new empty file in your current working directory.
echo "text" > <file> Shell Safe Writes text into a file. Use single > to overwrite or double >> to append lines.
ls / cat / rm / mv Shell Safe Standard shell helpers: ls lists directory contents, cat <file> prints contents, rm <file> deletes, and mv moves/renames.
clear Shell Safe Clears the output terminal window.

Common Git Errors & Quick Solutions

❌ "rejected - non-fast-forward (fetch first)"

Cause: Someone pushed new commits to remote main while you were offline.
Fix: Run git fetch origin ➔ git merge origin/main ➔ git push origin main.

❌ "Your local changes would be overwritten by checkout"

Cause: You edited files that differ on the target branch.
Fix: Run git stash ➔ switch branch ➔ git stash pop to restore your edits.

❌ "fatal: refusing to merge unrelated histories"

Cause: Local repo and remote repo were initialized independently.
Fix: Run git merge origin/main --allow-unrelated-histories.

❌ "Merge conflict in "

Cause: Two commits edited the exact same line of a file.
Fix: Edit file to remove <<<<<<< markers, run git add <file>, then git commit.

Git Mental Models & Concepts

The Three States

Files exist in three places: Working Directory (local disk edits), Staging Area / Index (prepared for commit), and Repository (frozen commit history graph).

Branches are just Pointers

A branch in Git is not a full copy of your directory. It is simply a 40-character SHA pointer pointing to a single commit. Switching branches moves the HEAD reference.

Fast-Forward vs Merge Commit

A Fast-Forward slides a branch pointer forward when no independent commits exist on the target branch. A Merge Commit joins two divergent branches with a 2-parent commit.

Upstream vs Origin vs Local

Upstream is the canonical maintainer repository. Origin is your personal fork on GitHub. Local is the working folder on your computer.

The Reflog Safety Net

Git never immediately deletes commits. Every movement of HEAD is logged in git reflog. Even after git reset --hard, your work is recoverable using its SHA.

Safe vs Destructive Rewrites

Adding commits (commit, merge, revert) is safe anywhere. Rewriting history (rebase, amend, reset) should only be done on unshared local feature branches.
